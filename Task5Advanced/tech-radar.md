### Архитектурные паттерны

| Паттерн | Статус | Обоснование |
|---------|--------|-------------|
| Data Mesh | Adopt | Целевая подход, который обеспечит независимость доменов |
| Event-Driven Architecture | Adopt | Основа междоменной интеграции, замена ESB на асинхронную публикацию событий |
| Domain-Driven Design | Adopt | Методология выделения контекстов и продуктов данных |
| Federated Computational Governance | Adopt | Управление стандартами через автоматизацию политик в DataHub |
| Self-service BI / Analytics | Adopt | Конечная цель: аналитики самостоятельно находят и используют продукты данных |
| Централизованное DWH | Hold | Замещается доменными витринами и озёрами; поддерживается только до миграции |
| Интеграционная шина (ESB/Camel) | Hold | Заменяется событийным взаимодействием через Kafka |

### Технологии и инструменты

| Технология | Статус | Назначение |
|------------|--------|------------|
| DataHub | Adopt | Единый каталог данных, lineage, управление политиками и качеством |
| Kafka | Adopt | Шина событий доменов, хранение и доставка событий |
| Apache Spark | Adopt | Основной движок ETL/ELT в финансовом домене и общих пайплайнах |
| dbt | Adopt | Трансформации в аналитических контекстах |
| ClickHouse | Adopt | OLAP-витрина в медицинском домене для быстрых аналитических запросов |
| PostgreSQL | Adopt | Операционные БД и реляционные витрины |
| Delta Lake | Adopt | Формат аналитических озёр, обеспечивающий ACID и time-travel |
| Apache Flink | Trial | Сложная стриминговая обработка с состоянием |
| Kubernetes | Adopt | Оркестрация контейнеризированных компонентов платформы. |
| Prometheus + Grafana | Adopt | Мониторинг платформы и доменных пайплайнов. |
| Tableau / PowerBI | Adopt | BI‑инструменты, подключаемые к витринам через продукт‑API |
| DWH (SQL Server) | Hold | Заменяется облачным объектным хранилищем + Spark |
| Apache Camel | Hold | Выводится из эксплуатации по мере перехода на событийную интеграцию |
